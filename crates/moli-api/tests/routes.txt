# Every route of the API, who may call it, and whether it is reached from outside the house.
# `routes.rs` compares this list with the router and checks each level against a live server
# (from the test's own machine, so "household"). The model behind it: docs/SECURITY-MODEL.md.
#
# Level:
#   public  a stranger (Internet, no proof) is let through: sign-in and invitation only.
#   foyer   a stranger is refused (403); the household's devices may call it.
#   humain  as foyer, and the household too is refused (403) without a person signed in with the
#           house's code (some of these also need an owner).
#
# Remote (`oui` / `non`): reached through a remote entry (VPN, proxy, tunnel) or not. Least
# privilege (I4): what an agent, a satellite, a machine or the installation calls, and what writes
# secrets, stays at home. Checked now: every route says it, the sign-in stays reachable, MCP stays
# at home; enforced on the remote entries when they exist (docs/SECURITY-MODEL.md, step 2).
#
# Limit: a handler that reads the person only after the body is parsed cannot be probed with an
# empty body (it answers 400/422 first); such routes are listed `foyer` until they get a probe.
