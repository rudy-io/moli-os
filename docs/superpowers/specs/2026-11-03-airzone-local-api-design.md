# Airzone Local API complete coverage

The requested outcome is coverage of every documented operation and parameter in the official Local API 1.78, building on the merged native driver. Cloud API, manufacturer thermostat pairing and undocumented schedules are separate protocols, not silently included in this claim. No real-house writes or deployment are part of implementation validation.

Keep existing device identities and guarded shared-control membership. Extend the same driver with a bounded, typed parameter registry used for reading, point publication and command validation. Cover zone, system, domestic hot water, IAQ, Webserver, version and integration metadata. Add explicit typed client support for all twelve operations, including GET alternatives, diagnostic demo and thermostat HTML; demo content is never published as live devices and remote HTML is never rendered inside Moli.

Read-only defaults to true and blocks writes at publication, execution and transport boundaries. Writes remain single, addressed, deadline-bounded and never retried. Parameter presence, current capabilities, units, integer/step constraints and cross-field relationships are checked afresh. System/controller operations include every affected zone directly in guard membership. Unsupported optional sections must not take healthy HVAC zones offline; their stale points must not remain actionable.

Publish every valid, present documented reading with bounded output and FR/EN labels. Normalize explicitly documented aliases, rejecting conflicting aliases. Unknown fields never authorize writes. Ambiguous documentation is recorded and handled conservatively; unproven units are not converted into energy costs. Represent optional capabilities only when the controller supplies them. Malformed essential zone measurements, units or master capabilities retain the original fail-closed isolation policy; invalid optional humidity/demand readings are omitted individually. Keep a machine-readable coverage inventory and tests that compare it with implementation, plus an explicit list of specification errata.

Reuse Moli's device points, history, guard, configuration and catalogue. A generic text-point editor may be needed for documented name/integration-version writes; it must preserve read-only and offline restrictions. Do not add a parallel storage, public raw HTTP proxy or arbitrary write endpoint. Device discovery means reading the gateway inventory, not physical thermostat pairing.

Implementation choices: Rust existing transport/runtime; Svelte existing controls; no new production dependency. Synthetic fixtures and loopback servers establish protocol behavior, not hardware certification. Run project checks and independent review before publishing a PR. Commits use only the user's configured identity.
